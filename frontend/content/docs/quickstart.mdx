# Quickstart

Two entry points: **web app** (recommended if you have a running Kova instance) or **local Docker/manual setup** for self-hosting. Both lead to the same first run: a project URL, optional credentials, discovery, and a validation that produces evidence.

## Path A — Web app first run

Use this when you open a Kova instance in a browser. Default hosted instance: **`https://kova-9269c6.rumptycloud.app`**. Docs and app share the same origin you are reading from.

### 1. Create an account

Open [Sign up](/auth/signup) on your Kova instance and register with email and password. Then sign in at [Log in](/auth/login).

### 2. Complete onboarding

After sign-in, open [Onboarding](/onboarding):

1. **Project** — name and base URL of the application under test
2. **Credentials** — optional login details for the application
3. **Discovery** — Kova opens an isolated browser and explores the app
4. **First validation** — run an initial check against the discovered flows

You can re-open the wizard at any time.

### 4. Create an API token (optional)

For CI or scripts: [Settings → API tokens](/settings/tokens). Tokens look like `kova_tok_...`. The raw token is shown once; store it securely. See [Authentication](guides/authentication).

## Path B — Local setup first run

Use this when you clone the repository and want everything on your machine. Developers only.

### Prerequisites

- Docker 24+ and Docker Compose v2, **or**
- Python 3.12+, Node 20+, PostgreSQL 16, Redis 7 (see [Local setup](development/local-setup) for manual steps)

### Docker Compose

```bash
cp .env.example backend/.env
# Optionally edit backend/.env (DATABASE_URL, JWT secrets, AI keys)
docker compose up -d
```

Services:

| Service | URL |
|---|---|
| Frontend | http://localhost:3000 |
| API | http://localhost:8000 |
| Health check | http://localhost:8000/health |

Open http://localhost:3000, sign up, and continue with Path A steps 2–4.

### Manual (no Docker for app services)

Follow [Local setup](development/local-setup): start Postgres and Redis, install backend deps, run migrations, start uvicorn + Celery, then `npm run dev` in `frontend/`. Point the frontend at the API with `NEXT_PUBLIC_API_URL=http://localhost:8000`.

## First API-only smoke test

Once you have a token and a project ID:

```bash
# Health
curl -s http://localhost:8000/health

# Register (local API; adjust host if not localhost)
curl -s -X POST http://localhost:8000/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.com","password":"your-password"}'
```

Then create a token via the UI or `POST /api/v1/auth/tokens`, and trigger a CI run as described in [CI/CD](integrations/ci-cd).

## What “done” looks like

A completed run shows status **COMPLETED** (or a terminal failure status), a step timeline, screenshots/frames, and a verification verdict. See [Results and evidence](guides/results-and-evidence).
